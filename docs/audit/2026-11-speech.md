# Speech path audit, November 2026

Ground truth for the external review of local Parakeet, You/Them separation and speaker echo. Every line below was checked against the tree at `a22f989`, not against review text.

## Capture constraints

- Microphone: `renderer/renderer.js:1910` calls `getUserMedia` with `echoCancellation: browserProcessing`, where `browserProcessing` is the browser-processing setting. A second path at `4457` uses `echoCancellation: true`.
- System audio on macOS: ScreenCaptureKit helper. Windows: Chromium loopback through `setDisplayMediaRequestHandler` (`main.js:4718`), gated on a trusted renderer, a user gesture and both video and audio requested. Linux: `parec` on the default sink monitor.
- `restrictOwnAudio` is not set anywhere. On Windows the app's own playback can be captured as Them.

## Echo handling that already exists

`src/acoustic-echo-filter.js` is real and wired in. `observeSystem(pcm)` records system audio; `main.js:2299` calls `inspectMicrophone(pcm)` before routing mic audio and returns early when `echo.suppress` is true, counting `acousticEchoSuppressed`.

What it does: downsamples both tracks by 8, keeps about 2 s of system history, searches lags up to 1.5 s, and suppresses the mic chunk when normalized correlation exceeds 0.82 and the reference has meaningful energy.

What it does not do:

- It has no double-talk veto. A chunk where the user talks over the remote can correlate and be dropped whole.
- It aligns by pushing buffers, not by a shared sample index stamped at capture.
- It has no text-level cross-channel deduplication of its own, but the transcript layer already has one: src/transcript-dedupe.js (findCrossTalkDuplicate, crossTalkScore) removes a finalized Them turn duplicated by a You turn inside a rolling window. So the review's "no text dedup" claim is also out of date.
- It has no "speakers detected" state or user-visible count.

So the review's statement that nothing detects echo is wrong. Its conclusion that the no-headphones case is unprotected is only partly wrong: chunks that are pure bleed are dropped, but overlap and residual echo are not handled.

## Model ownership and concurrency

One `LoadedModel` owns one `Session` (`native/speech-worker/src/main.rs:17`). Per-channel `ActiveStream` values live in a single `HashMap` and all stream commands are serialized through one worker queue. There are not two loaded models and not two sessions. The review's "two sessions, double memory, crash risk" concern does not apply as written.

Memory still scales with per-channel stream state, so the routing budget check for two channels remains correct.

## Build and packaging

- `native/speech-worker/Cargo.toml` pins transcribe.cpp by exact git revision `60bed89dab84f7c1fddc3a17ad7fa8a27ddfba19`, with Metal on macOS and no default features elsewhere.
- `scripts/build-speech-worker.js` sets portable CMake arguments: `GGML_NATIVE=OFF`, `TRANSCRIBE_X86_CONSERVATIVE=ON`, no system BLAS, no OpenMP, deployment target 13.0 on macOS.
- `scripts/before-pack.js` builds the worker during packaging, and `npm run verify:speech-package` runs in CI at `ci.yml:104`, `158`, `204`.
- Vulkan is opt-in through `VOLYX_LENS_SPEECH_VULKAN=1` or a pack context flag.
- The whisper-server sidecar files still exist: `src/whisper-runtime-manifest.js`, `scripts/prepare-whisper-runtime.js`.

## Documentation

- `README.md:113` correctly names v0.8.9 as the current release.
- The README already documents the local GGUF engine (registry, streaming models, VAD, CPU/GPU selection) at lines 77 and 266, contrary to the review's claim that only local Whisper is described.
- One genuine mismatch was fixed: line 266 claimed two independent streaming sessions. The worker actually loads one model in one session with per-channel stream state and serialized inference.
- The README now explains speaker echo, the signal filter, double-talk and the text-level second line of defence.

## Gaps worth fixing, in order

1. Double-talk protection in the echo filter, so correlated but genuine speech is not dropped.
2. Text-level dedup as a second line of defence for residual echo.
3. Them-channel silence watchdog after the channel has carried sound, plus `restrictOwnAudio` on Windows and a guard against choosing an output-only device as the mic.
4. A user-facing speaker/headphones note and an echo-suppressed count.
5. Documentation for the local engine.
6. Fallback to batch on a CPU-only backend for streaming, if measurements show it lags.
7. Signed and notarized macOS builds; needs credentials, not code.

## Not verified here

- Real speaker-mode recordings. Thresholds are untuned against real rooms.
- Whether the SCK helper excludes the app's own audio.
- Accuracy differences between streaming and batch on the same audio.
